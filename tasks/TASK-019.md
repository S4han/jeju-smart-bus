### 2. 원인별 안내
- 화면 위 "서비스 상태 안내"(`ServiceNotices`): 원인 문구 + "이용할 수 없는 기능" + "계속 이용할 수 있는 기능"(여러 서비스가 함께 멈추면 모두 반영)
- 원인: 연결 실패 / 요청 많음(`rate_limited`) / 이용 한도 도달(`quota_exhausted`) / 자료 불일치(`inconsistent`)
- 도착정보 영역: 원인별 문구 + "정류장 검색·주변 정류장·경로 찾기는 계속 이용할 수 있습니다". 실패 시 이전 값·추정치 미표시
- 지도 실패(SDK 로드·인증 실패, NAVER 한도 도달 차단 포함 — D-15): PoC 상태 문구(`STATUS_MESSAGES`)는 그대로 두고 안내 영역에 영향 기능 추가

### 3. 한도·호출 제한 감지 (D-11 무상태)
- 서버 `server/arrivals.ts`: HTTP 429 또는 `resultCode 23` → `rate_limited`(429, `Retry-After: 5`), `resultCode 22` → `quota_exhausted`(503). **제주 BIS에서 이 응답들은 아직 관찰된 적 없음 — 공공데이터포털 공통 코드·HTTP 표준에 대비한 미검증 매핑**
- 반복 호출 억제(세 겹):
  1. 함수 인스턴스 메모리: 한도 소진 뒤 10분, 호출 제한 뒤 5초 동안 상류 호출 없이 같은 응답(인스턴스 간 공유 안 됨 — R-09 보조 수단)
  2. 브라우저: 한도 소진을 받으면 10분 동안 `/api/arrivals` 요청 자체를 보내지 않음
  3. CDN: 한도 소진 응답에 `s-maxage=60` — **Vercel이 503 응답을 캐시하는지는 문서로 확인하지 못함(미검증)**
- 외부 KV·DB 미사용
- 값(10분·5초·60초)은 미확정 설정값

### 4. 자동 과금 서비스 배제 재확인 (GATE-06)

### 5. 재시도 정책
- 브라우저: `rate_limited`·시간 초과(504)·네트워크 오류만 지수 백오프 1초 → 2초, 최대 2번 더(총 3회). `quota_exhausted`·상류 오류(502)·잘못된 요청(400)은 재시도 없음. 무한 재시도 없음
- 서버: 상류 재시도 없음(1회 호출)
