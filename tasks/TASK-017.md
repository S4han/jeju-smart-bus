## PRD 수용 기준 (원문)
- **AC-010:** 각 구성요소가 계산 가능하면 총 소요시간을 합산하고 출처·추정 여부를 구분한다. 필수 구성요소가 검증되지 않으면 임의 수치로 채우지 않고 총 소요시간 미확인으로 처리한다. 중복 합산 방지 산식은 U-002로 검증한다.
- **AC-011:** 50분/0회/5분 경로는 50분/0회/12분보다 앞서고, 두 경로 모두 50분/1회/8분보다 앞선다. 55분/0회 경로는 그 뒤에 온다. 세 수치가 모두 같으면 고정 식별자 순이며 동일 입력의 정렬 결과는 항상 동일하다.
- **AC-012:** 유효 경로가 4개 이상이어도 FR-011 정렬 상위 3개만 시간 기준 추천 영역에 표시한다. 1~2개라면 존재하는 개수만 표시한다.
- **AC-015:** 환승 횟수 오름차순으로 정렬한다. 같은 환승 횟수에서는 도보거리 확인 가능 경로를 먼저 배치하고, 확인 가능 경로끼리는 도보거리 오름차순, 같은 거리 또는 확인 불가 경로끼리는 고정 식별자 순으로 정렬한다. 상위 5개만 표시하며 총 소요시간을 임의 기입하지 않는다. 최대 환승 2회 제한을 준수한다.

## 작업 항목
1. 시간 합산: 승인된 산식(GATE-05)으로 구성요소 합산, 각 구성요소 출처(실시간/추정) 보존, 하나라도 미검증 → `totalTime: unknown`
2. 추천 정렬 비교자: 총 소요시간 → 환승 횟수 → 도보시간 → 고정 식별자 (모두 오름차순)
3. 시간 미확인 정렬 비교자: 환승 횟수 → 도보거리 확인 가능 우선 → 도보거리 → 고정 식별자
4. 고정 식별자 생성(D-07): 예) 직행 `201:405001>405120`, 1회 환승 `201:405001>405050|311:405050>406010`. 비교는 `localeCompare` 대신 `<`/`>` 코드 단위 비교. 결정적 정렬(안정 정렬 의존 금지, 최종 키로 식별자 사용). 위 ID 값은 형식 예시이며 실제 ID 형식은 GATE-01·02 확인 후 적용
5. 상위 N 선택(3, 5) 상수화

## 테스트 케이스
- AC-011 예시 그대로: [50/0/5, 50/0/12, 50/1/8, 55/0/x] 순서 검증, 입력 순서를 섞어도 결과 동일
- 세 수치 동일 → 식별자 순
- 식별자 생성: 같은 경로 입력 → 항상 같은 문자열, 구간 순서가 다르면 다른 문자열 (D-07)
- 유효 경로 4개 이상 → 3개 / 2개 → 2개 (AC-012)
- 구성요소 하나 미검증 → 추천 영역 제외, 시간 미확인 영역으로 이동, 시간 수치 미표시 (AC-010)
- AC-015: 같은 환승 횟수에서 도보거리 확인 가능 경로가 불가 경로보다 앞섬, 거리 동률·불가끼리 식별자 순, 6개 이상 → 5개
- 추정 구성요소 포함 시 "추정" 표시 유지
