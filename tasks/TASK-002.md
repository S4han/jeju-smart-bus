## 목적
현재 위치·선택 위치 좌표가 어디로 흐르고 어디에 남을 수 있는지 전 구간을 문서화하고, PRD 확정 정책(서버 DB 영구 저장 금지, 로그·캐시 최소화, 외부 API 처리 조건 검증)을 충족하는 설계인지 판정한다.

## 선행 조건
- [x] D-01 승인(2026-10-26): 정적 스냅샷 + 브라우저 탐색, 서버는 정류장 ID만 수신 — 이 구조를 검증 대상으로 함
- [x] D-13 승인(2026-10-26): Web Analytics·Speed Insights·로그 드레인 미사용
- [x] D-12 결정(2026-10-26): 사용자 직접 검토 — 체크리스트 PRIV-001-004.md §8, 결과는 출시 전까지 필요

## 범위
- 포함: 데이터 흐름도, 로그·캐시·외부 API 정책 문서, 공급자 약관·개인정보 처리 조건 조사(문서 열람), 검증 체크리스트
- 제외: 애플리케이션 코드, 외부 API 실호출

## 작업 항목
1. **좌표 흐름도:** 브라우저(Geolocation, 메모리 상태, URL/history, localStorage) → 지도 SDK → 장소 검색 API → 도보 API → 자체 서버 함수 → 버스 API. 각 지점의 전송 여부·저장 여부·보존 기간 기록
2. **PRIV-001 (DB 영구 저장):** 서버 측 DB·KV·파일 저장소 미사용 확인, 서버 함수가 좌표를 받지 않거나(D-01 A안) 받더라도 저장하지 않는 설계
3. **PRIV-002 (로그):** Vercel 접근 로그·런타임 로그·빌드 로그, 브라우저 오류 리포트, 분석 도구에서 좌표 기록 가능 지점 식별. 규칙: 좌표 쿼리스트링 금지, 요청 본문 로그 금지, 분석 도구 미사용(D-13), 오류 메시지에 좌표 미포함
4. **PRIV-003 (캐시):** CDN 캐시·브라우저 캐시·Service Worker·localStorage. 규칙: 좌표 포함 응답 `Cache-Control: no-store`, 정류장 ID 단위 응답만 공유 캐시 허용, 좌표를 URL에 넣지 않아 history·공유 링크에 남지 않게 함
5. **PRIV-004 (외부 API):** NAVER 지도 SDK(뷰포트·타일 요청 좌표 포함), 장소 검색 후보(U-001), 도보 데이터 후보(U-002)의 약관·개인정보 처리방침에서 전달 좌표의 저장·재이용 조건 조사
6. 위치정보 수집 시 사용자 고지 문구 초안(권한 요청 전 설명) — 법적 문구 확정은 D-12

## 수용 기준
- PRIV-001~004 각각 **통과 / 조건부 통과(조건 명시) / 보류** 판정과 근거가 기록되어 있다.
- 좌표가 거치는 모든 구간이 흐름도에 표시되어 있다.
- 로그·캐시 규칙이 구현자가 체크할 수 있는 항목으로 작성되어 있다.
- 보류 판정 항목과 연결된 기능(TASK)이 명시되어 있다.

## 검증 방법
