## 목적
총 소요시간 = 도보 + 대기 + 버스 이동 + 환승에 필요한 시간(PRD §3)의 각 구성요소를 **검증된 근거**로 산정할 수 있는지, 중복 없이 합산하는 산식을 제안한다.

## 선행 조건
- [x] TASK-005(GATE-04), TASK-006(GATE-02·03) 결과
- [x] D-06 결정 방식 승인(2026-10-26): 이 TASK 결과로 도보시간 원천을 제안, 사용자 확정
- [x] 도보 데이터 후보 조사 범위(이번 검증은 외부 도보 API 미호출 — 비교만, GATE-05 §5)(기본: Kakao 도보 경로 — GATE-06 §3.4, TMAP — 접근 차단, 직선거리 추정, 미제공), 필요 시 PRIV-004·GATE-06 검증

## 작업 항목
1. 구성요소별 원천 후보: 도보(API/추정/없음), 대기(실시간 도착/시간표), 버스 이동(구간 시간표/운행 데이터), 환승(환승 도보 + 다음 버스 대기)
2. 중복 위험 식별: 예) 환승 시 "환승 도보시간"과 "다음 버스 대기시간"의 겹침, 실시간 도착 예정 시각에 이미 이동시간이 포함되는 경우
3. 산식 제안서: 각 항목의 출처 표시(실시간/추정/미확인), 하나라도 미검증이면 "총 소요시간 미확인" 처리(AC-010)
3-1. 도보시간 원천 비교(D-06): 도보 API(좌표 외부 전달·서버 경유 여부 R-18, 무료 한도 — Kakao 일 1,000건), 직선거리×보정계수 추정("추정" 표기, 오차 근거 필요 — 검증된 근거 해당 여부는 사용자 판단), 미제공(해당 경로 시간 미확인). 각 안이 FR-010·FR-015·PRIV-004에 미치는 영향 정리
4. 샘플 경로 수작업 계산 예시

## 결과 (2026-10-26)

`docs/verification/GATE-05.md` 참조. 상류 호출 8회(사용자 승인), 임시 프로브에 `BusArriveList`·`BusArriveInfo` 조회 추가(미리보기 전용).
- `BusArriveList`: 순번·정류장 ID 모두 0건 → 사용 불가
- `BusArriveInfo`: `station` 값 무시, 노선의 정류장마다 "가장 먼저 도착할 차량"의 예측 분 제공 → **같은 차량의 두 정류장 예측 차로 구간 이동시간(실시간 예측) 산정 가능**
- 판정 **부분 통과**: 승차 정류장 차량을 제때 탈 수 있고, 승차~하차(·환승 후 구간)가 같은 차량의 예측으로 이어질 때만 산정. 그 밖에는 미확인
- 중복 없는 산식: 총 소요시간 = 마지막 하차 정류장 도착 예정(실시간 예측) + 목적지 도보. 출발지 도보는 대기와 겹치므로 "제때 도착" 판정에만 사용
- 예측 안정성 관찰 1건: 대기 예측 2분 사이 2분 앞당겨짐, 구간 차이는 변화 없음. 정확도(실제 도착 대비)는 미측정
- 사용자 결정: D-06(도보 근거), D-30(노선 ID 조회), D-31(여유 시간), 실시간 예측을 근거로 인정할지
