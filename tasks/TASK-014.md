# TASK-014 — 정류장 도착정보(FR-005)·시간표 기반 추정(FR-014)

| 항목 | 내용 |
|---|---|
| Phase | 2 — 도착정보 |
| 상태 | 구현 완료(브랜치, 2026-10-26) — 실호출 확인은 사용자 승인 대기. FR-014는 "추정 없음" 동작만(R-21) |
| 관련 | FR-005, FR-014, AC-005, AC-014, US-002, US-006, GATE-04 |

## 목적
선택한 정류장의 검증된 실시간 도착정보를 보여주고, 없을 때 검증된 시간표가 있으면 "추정"으로 구분해 보여준다.

## 선행 조건
- [x] TASK-005 GATE-04 판정(2026-10-26): 실시간 통과(조건부), 시간표 대체 근거 없음 — `docs/verification/GATE-04.md`
- [x] TASK-004 서버 프록시, TASK-013 정류장 선택(브랜치)
- [x] D-04 확정(2026-10-26): 행 단위 `calcDate`, 조회 시각 기준 120초 이내만 "실시간"

## PRD 수용 기준 (원문)
- **AC-005:** 선택한 정류장 ID로 도착정보를 조회하고 해당 정류장의 버스 도착정보만 표시한다. 응답이 없거나 오래된 경우 실시간 정보가 있는 것처럼 표현하지 않는다.
- **AC-014:** 실시간 도착정보가 없고 검증된 대체 데이터가 있을 때만 추정 정보를 제공하며 **실시간**과 **추정**을 명확히 구분한다. 대체 데이터도 없으면 추정치를 만들지 않는다.

## 작업 항목
1. 서버 프록시 호출(정류장 ID만 전송), 응답의 정류장 ID 일치 검증 — 불일치 항목 제외
2. 신선도 판정(D-04 확정): **행마다** 조회 시각 − `calcDate` ≤ 120초면 실시간, 초과·누락·해석 불가면 `stale`(실시간 표기 금지). 120초는 설정값으로 분리. `arrvVhId=0`·`predictTravTm=0` 행은 "도착 예정 차량 없음"(GATE-04 §1). 정류장 ID는 정적 스냅샷에 있는 것만 요청
2-1. 상류 호출은 `serviceKey` 없이(D-25), 응답 오래된 행 혼재(GATE-04)
3. 실시간 없음 + 검증된 시간표 있음 → "추정" 라벨(텍스트 + 시각 구분, 색만으로 구분하지 않음)
4. 둘 다 없음 → "도착정보 없음" 표시, 수치 미표시
5. 장애·한도 상태는 TASK-019 공통 안내 사용

## 테스트 케이스
- 다른 정류장 ID가 섞인 응답 → 해당 항목 제외
- 빈 응답 → "정보 없음", 실시간 표기 없음
- `calcDate`가 121초 전인 행 → 실시간 표기 없음, 120초 전 → 실시간 (D-04 경계)
- 같은 응답에 최신 행과 2025년 행이 섞여도 최신 행만 실시간 (실응답 픽스처 `tests/fixtures/bis/bus-arrives-items.json`)
- `arrvVhId=0` 행 → 차량 없음 처리
- 실시간 없음 + 시간표 있음 → "추정" 표기
- 실시간 없음 + 시간표 없음 → 추정치 미생성

## 보류 조건
GATE-04 실시간 불가 → 실시간 기능 보류, 사용자 보고. 시간표 불가 → FR-014는 "추정치 없음" 동작만 구현하고 재검토 요청.

## 결과 (2026-10-26)

### 구조
- **서버** `server/arrivals.ts`(`GET /api/arrivals?stopId=`): 정류장 ID(숫자 9자리 — 스냅샷 정류장 4,352개 전부 해당)만 받아 `BusArrives?station=`을 키 없이 호출(시간 제한 8초). 행을 `toArrival`로 변환하고 **조회 시점 데이터 나이**(`ageSecondsAtFetch`)를 붙여 반환. 형식 오류 행은 버리고 개수만(`invalidRows`)
  - 성공: `Cache-Control: public, max-age=0, s-maxage=15`(정류장 ID 단위, 좌표 없음 — D-22). 15초는 **미확정 설정값**
  - 실패: HTTP 오류·`resultCode`≠`00`(점검 HTML 포함) → 502, 시간 초과 → 504, 접속 불가 → 502. 모두 `no-store`, 데이터 없음
  - 로그 출력 없음
- **판정** `shared/arrivals.ts`(브라우저에서 실행):
  1. AC-005 정류장 일치: 응답 행 (노선, 순번)이 스냅샷에서 이 정류장을 가리킬 때만 사용 — 아니면 제외(`mismatched`)
  2. 차량 없음(`arrvVhId=0`)·시간 없음 → 실시간으로 쓰지 않음
  3. D-04: **화면 시점 나이 = 조회 시점 나이 + CDN 체류(`Age` 헤더) + 받은 뒤 경과(`performance.now`)** ≤ 120초만 실시간. 기기 시계를 쓰지 않는다. 산출 시각이 60초 넘게 미래면(시계 이상) 실시간 아님(60초는 **미확정 설정값**)
  4. 화면을 열어 두면 10초마다 다시 판정 → 120초가 지나면 실시간 표시가 사라짐
- **`calcDate` 해석** `parseBisDateTime`: 시간대 표기가 있으면 그대로, 없으면 한국 시간. `YYYY-MM-DD HH:mm:ss`·`YYYYMMDDHHmmss`·ISO 허용, 그 밖은 null → 행 폐기. **원문 형식은 실호출로 재확인 필요**(기록된 픽스처는 ISO+09:00)
- **화면** `src/arrivals/ArrivalPanel.tsx`: 주변 정류장을 고르면 표시. 실시간 행만 "N분 후 · M정류장 전 [실시간]"(텍스트 배지), 빠른 순. 나머지 노선은 "실시간 도착정보 없음" 개수만. **"시간표 자료가 없어 추정 도착시간은 제공하지 않습니다"** 고정 안내(FR-014·AC-014 — 대체 데이터 없음 → 추정치 미생성). 새로고침 버튼
