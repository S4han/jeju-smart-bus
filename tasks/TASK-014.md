# TASK-014 — 정류장 도착정보(FR-005)·시간표 기반 추정(FR-014)

| 항목 | 내용 |
|---|---|
| Phase | 2 — 도착정보 |
| 상태 | 미착수 |
| 관련 | FR-005, FR-014, AC-005, AC-014, US-002, US-006, GATE-04 |
| 결정 의존 | D-04 |

## 목적
선택한 정류장의 검증된 실시간 도착정보를 보여주고, 없을 때 검증된 시간표가 있으면 "추정"으로 구분해 보여준다.

## 선행 조건
- [x] TASK-005 GATE-04 판정(2026-10-26): 실시간 통과(조건부), 시간표 대체 근거 없음 — `docs/verification/GATE-04.md`
- [ ] TASK-004 서버 프록시, TASK-013 정류장 선택
- [x] D-04 확정(2026-10-26): 행 단위 `calcDate`, 조회 시각 기준 120초 이내만 "실시간"

## PRD 수용 기준 (원문)
- **AC-005:** 선택한 정류장 ID로 도착정보를 조회하고 해당 정류장의 버스 도착정보만 표시한다. 응답이 없거나 오래된 경우 실시간 정보가 있는 것처럼 표현하지 않는다.
- **AC-014:** 실시간 도착정보가 없고 검증된 대체 데이터가 있을 때만 추정 정보를 제공하며 **실시간**과 **추정**을 명확히 구분한다. 대체 데이터도 없으면 추정치를 만들지 않는다.

## 작업 항목
1. 서버 프록시 호출(정류장 ID만 전송), 응답의 정류장 ID 일치 검증 — 불일치 항목 제외
2. 신선도 판정(D-04 확정): **행마다** 조회 시각 − `calcDate` ≤ 120초면 실시간, 초과·누락·해석 불가면 `stale`(실시간 표기 금지). 120초는 설정값으로 분리. `arrvVhId=0`·`predictTravTm=0` 행은 "도착 예정 차량 없음"(GATE-04 §1). 정류장 ID는 정적 스냅샷에 있는 것만 요청
2-1. 상류 호출은 `serviceKey` 없이(D-25), 응답 오래된 행 혼재(GATE-04)
3. 실시간 없음 + 검증된 시간표 있음 → "추정" 라벨(텍스트 + 시각 구분, 색만으로 구분하지 않음)
4. 둘 다 없음 → "도착정보 없음" 표시, 수치 미표시
5. 장애·한도 상태는 TASK-019 공통 안내 사용

## 테스트 케이스
- 다른 정류장 ID가 섞인 응답 → 해당 항목 제외
- 빈 응답 → "정보 없음", 실시간 표기 없음
- `calcDate`가 121초 전인 행 → 실시간 표기 없음, 120초 전 → 실시간 (D-04 경계)
- 같은 응답에 최신 행과 2025년 행이 섞여도 최신 행만 실시간 (실응답 픽스처 `tests/fixtures/bis/bus-arrives-items.json`)
- `arrvVhId=0` 행 → 차량 없음 처리
- 실시간 없음 + 시간표 있음 → "추정" 표기
- 실시간 없음 + 시간표 없음 → 추정치 미생성

## 보류 조건
GATE-04 실시간 불가 → 실시간 기능 보류, 사용자 보고. 시간표 불가 → FR-014는 "추정치 없음" 동작만 구현하고 재검토 요청.
