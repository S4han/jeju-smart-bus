| 항목 | 내용 |
|---|---|
| Phase | 1 — 기반 |

## 목적
`src/App.tsx`에 있는 NAVER 지도 SDK 로딩·지도 생성 로직을 재사용 가능한 모듈로 분리하되, 기존 동작을 그대로 유지한다.

## 선행 조건
- [x] TASK-001 PoC 회귀 체크리스트 확정
- [x] D-17 승인(2026-10-26): Client ID 브라우저 노출 예외, 허용 URL 최소화 조건
- [x] D-18 승인(2026-10-26): 신규 화면에 흡수, 회귀 체크리스트로 보존(별도 경로 없음)
- [x] PRIV-004 §6.1 조건부 — 이 TASK는 고정 중심(제주시)만 다루고 사용자 위치로 지도를 옮기지 않으므로 영향 없음(사용자 위치 중심은 TASK-011·013에서 별도 확인)

## 작업 항목
1. SDK 로더: 1회만 스크립트 삽입(StrictMode 중복 실행 대응), 로드 상태(로딩/성공/인증 실패/로드 실패) 반환. 기존 오류 메시지 문구 유지
2. 지도 컴포넌트: 중심·확대 수준·마커 목록(좌표 있는 항목만)·선택 상태를 props로 받음
3. `@types/navermaps` 타입 적용(`any` 제거)
4. 기존 화면은 분리된 모듈을 사용해 **동일하게** 렌더링

## 수행 결과 (2026-10-26)

| 파일 | 내용 |
|---|---|
| `src/map/naverSdk.ts` | SDK 로더(`createNaverMapsLoader`): 스크립트 1회만 삽입, 상태 `loading`·`ready`·`missing_client_id`·`init_failed`·`load_failed`, SDK 인증 실패 전역 콜백(`navermap_authFailure`)을 늦은 실패로 전달. 기존 PoC 문구를 `STATUS_MESSAGES`로 그대로 유지. 브라우저 인스턴스는 처음 쓸 때 생성 |
| `src/map/useNaverMaps.ts` | 로드 상태 훅 |
| `src/map/NaverMap.tsx` | 지도 컴포넌트: 중심·확대 수준·항목·선택 상태를 props로 받음. 지도는 한 번만 생성, 마커는 항목 변경 시 교체 |
| `src/map/markers.ts` | 좌표가 확인된 항목만 마커 입력으로 변환(AC-004·AC-020, D-24) |
| `src/App.tsx` | 분리된 모듈로 같은 화면 구성(같은 DOM 구조·문구) |
| 타입 | `@types/navermaps` 적용, `any` 제거 |

검증:
- `npm run build` 성공, `npm test` 59개 통과(로더·마커 6개 추가 — 가짜 window·script 주입, 단일 삽입·상태 전이·인증 실패·문구 동일성·좌표 없는 항목 제외)
- 브라우저(Playwright, 360×740) — 운영 빌드 Client ID 없음: 안내 문구, SDK 요청 0, 스크립트 0, 가로 스크롤 없음
- 개발 서버(StrictMode) + 가짜 Client ID + SDK 요청을 스텁으로 대체:
  - 정상: SDK 요청 1회·스크립트 태그 1개, `Map(33.4996, 126.5312, zoom 11)`·`Marker("제주시")` 호출 — PoC와 동일, 완료 문구
  - 인증 실패 콜백: 초기화 실패 문구로 전환
  - 로드 오류: 로딩 실패 문구
  - SDK URL에는 Client ID 외 파라미터 없음
- 실제 NAVER 지도 렌더링·이동·확대는 실제 Client ID와 허용 URL이 필요해 미확인(미리보기 도메인은 NCP 허용 URL에 없을 가능성)

## 수용 기준
- PoC 회귀 체크리스트 전 항목 통과.
- 좌표가 없는 항목은 마커로 렌더링되지 않는다(테스트).
- 지도 SDK 요청 URL에 Client ID 외 키·사용자 좌표가 포함되지 않는다.
