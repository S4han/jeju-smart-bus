## 1. 실시간 도착정보 — `BusArrives?station=`

| 항목 | 실측 |
|---|---|
| 필드 | `arrvVhId`, `calcDate`, `leftStation`, `predictTravTm`(분), `routeId`, `stationOrd`, `updnDir` — 명세와 일치 |
| 응답 시간 | 0.2~0.6초, 약 9~14 KB |
| 한 정류장 응답 구성 | 그 정류장을 지나는 노선·순번마다 1행. 예: `406000191` 42행 중 차량 정보가 있는 행 6, `arrvVhId=0`·`predictTravTm=0` 36행 |
| **갱신 주기** | `calcDate`가 16:03:20 → 16:03:50 → 16:04:20으로 **30초 간격**. 조회 시점 기준 데이터 나이 30~54초 |
| **오래된 행 혼재** | 같은 응답 안에 `calcDate`가 2024-08-07, 2025-05-08 등인 행이 섞여 있음. 정류장 `405000153`(제주버스터미널)은 관찰한 행이 모두 2025-05-08 — 이 정류장의 최신 행 여부는 미측정 |
| 없는 정류장 ID | `resultCode 00` + 0건 — "잘못된 ID"와 "도착정보 없음"이 구별되지 않음 |
| `updnDir` | 관찰한 행 모두 0 |

판정 조건(FR-005·AC-005 반영 규칙, TASK-014):
1. **행마다 `calcDate`로 신선도 판정** — 응답 전체가 아닌 행 단위
2. `arrvVhId=0`이고 `predictTravTm=0`인 행은 "도착 예정 차량 없음"으로 해석(실시간 정보로 표시하지 않음) — 해석은 추가 관찰로 확인
3. 정류장 ID는 정적 스냅샷에 있는 것만 요청(없는 ID가 성공으로 응답되므로)

### D-04 기준값 제안 (사용자 확정 필요)

- 관찰된 갱신 주기 30초, 데이터 나이 최대 약 54초
- **제안: 조회 시각 − `calcDate` ≤ 120초이면 "실시간", 초과하면 `stale`로 실시간 표기 금지** (갱신 2회 누락까지 허용 + 여유)
- `calcDate`가 없거나 해석 불가하면 실시간으로 표기하지 않음

## 2. 시간표 대체 데이터 (FR-014)

| 원천 | 실측 | 판단 |
|---|---|---|
| `BusInfo?route=` (첫·막차, 배차 간격) | 운행 중 노선 `405320114`, 명세 예시 `406002021` **모두 0건** | 현재 근거로 사용 불가 |
| `Bus` 응답의 `firstTm`, `lastTm` 필드 | **명세에 없는 필드가 실제로 존재.** 일부 노선에만 값이 있음(샘플 5건에는 없음) — 채움 비율 미측정 | 첫·막차 시각일 가능성. 정류장별 시간표는 아님 |
| 정류장별 운행 시간표 | 명세·실측 모두 없음 | — |

판정: **검증된 정류장별 시간표 대체 데이터는 현재 확인되지 않음.** PRD AC-014("대체 데이터도 없으면 추정치를 만들지 않는다")에 따라 FR-014는 "추정 없음" 동작으로 구현 가능. 다만 FR-014의 실질 기능(추정 제공)은 데이터 부재로 제공되지 않을 수 있음 → **사용자 보고·범위 재검토 대상(R-02·R-21)**. `firstTm`·`lastTm` 채움 비율과 의미는 TASK-006에서 추가 확인.
