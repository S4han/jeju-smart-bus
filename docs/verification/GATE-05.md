### 발견
1. **`BusArriveList`는 실제로 데이터를 주지 않는다**(순번·정류장 ID 모두 0건) → 원천으로 사용 불가.
2. **`BusArriveInfo`는 `station` 값을 무시**하고(필수이나 값 무관), 해당 노선의 **각 정류장(순번)마다 "가장 먼저 도착할 차량"의 ID·남은 정류장 수·도착 예정 분(`predictTravTm`)·산출 시각**을 준다. 명세("노선·정류소별 도착")와 다르다.
   - 예(20:47:20 산출, 312-1 `405131201`): 차량 7983632 — 제주시청(광양방면, 23번째) 22분, 제주동초등학교(28번째) 32분 → **같은 차량의 두 정류장 예측 차이 = 10분(5개 정류장 구간 이동 예측)**
   - 예(20:48:20, 411-1 `405241101`): 차량 7983581 — 제주시청(66번째) 2분, 삼도119센터(71번째) 11분 → 9분
   - 한 노선 응답에 여러 차량이 정류장 구간을 나눠 담당(예: 7983574가 21~40번째, 7983558이 41~64번째, 7983581이 65~79번째). 차량이 없는 앞쪽 정류장은 행이 없음
   - 정류장 ID(`arrvStationId`)·순번이 함께 와서 스냅샷 노선과 대조 가능(AC-005 방식)
3. 구간 이동시간의 **정적 원천(시간표·구간 소요)은 여전히 없음**(`BusInfo` 0건 — GATE-04, `StationRoute`는 거리만).

## 4. 중복 없는 산식 제안 (사용자 승인 필요)

핵심: **실시간 예측의 "도착 예정 분"은 지금부터 그 차량이 정류장에 닿을 때까지의 시간**이므로, 승차 대기·버스 이동을 따로 더하지 않고 **마지막 하차 정류장 도착 예정 시각을 그대로 쓴다.** 출발지 도보는 대기 시간과 겹치므로(버스를 기다리는 동안 걸어감) 더하지 않고 "제때 닿을 수 있는가" 판정에만 쓴다.

기호: `W₀` 출발지→승차 도보(분), `W₁` 하차→목적지 도보(분), 구간 k의 차량 `Vₖ`, 정류장 s에서 Vₖ의 예측 도착 `P(Vₖ, s)`(분, 산출 120초 이내 행만 — D-04), 여유 `M_board`, `M_transfer`(D-31).

1. 첫 구간 차량 `V₁` = 승차 정류장 b₁의 "가장 먼저 도착할 차량". 조건 `W₀ + M_board ≤ P(V₁, b₁)` — 아니면 **총 소요시간 미확인**(다음 차 시각을 모름)
2. 각 구간 k: 하차 정류장 aₖ의 "가장 먼저 도착할 차량"도 `Vₖ`여야 함 — 아니면 미확인. 도착 `Tₖ = P(Vₖ, aₖ)`
3. 환승(k → k+1, 같은 정류장 t = aₖ = bₖ₊₁): 다음 노선의 t 차량 `Vₖ₊₁`에 대해 `P(Vₖ₊₁, t) ≥ Tₖ + M_transfer` — 아니면 미확인
4. **총 소요시간 = T_마지막 + W₁**
   - 구성 표시: 도보(W₀·W₁, 추정) · 대기(P(V₁,b₁), 실시간 예측) · 이동(각 구간 P 차이, 실시간 예측) · 환승 대기(P(Vₖ₊₁,t) − Tₖ, 실시간 예측) — **표시용 분해**이며 합계는 위 식(중복 없음)
   - 도보가 추정이면 전체 "추정 포함"(AC-010)
5. 정렬(AC-011)의 "도보시간" = W₀ + W₁

### 예시(§1 실측값, 도보는 D-06 미정이라 가정값으로만 계산 방식 시연)
- 312-1 직행, 승차 제주시청(광양방면) → 하차 제주동초등학교, 20:47:20 산출
  - P(7983632, 제주시청) = 22, P(7983632, 제주동초) = 32 → 같은 차량 ✔
  - 가정 W₀ = 3분(예: 직선 150m), W₁ = 4분: 3 + 1(M_board 가정) ≤ 22 ✔
  - **총 = 32 + 4 = 36분**(대기 22 · 이동 10 · 도보 3(겹침)·4). 단순 합산(3+22+10+4 = 39분)은 출발지 도보 3분을 중복 계산한 것
- 411-1 직행, 제주시청 → 삼도119센터, 20:48:20: P = 2, 11 → 같은 차량 ✔. W₀ = 3분이면 3 + 1 > 2 → **이 차량은 놓침 → 총 소요시간 미확인**(다음 차 미확인)

## 6. 산정 가능 범위(추정)

- 실시간 예측 차량이 승차 정류장 앞에 있고, 승차~하차 사이에 다른 차량이 없으며, 사용자가 제때 승차 정류장에 닿을 수 있는 경로만 → **경로·시각에 따라 크게 달라짐.** 표본 측정은 이번 범위에서 하지 않음(구현 후 TASK-020 재측정)
- 차량 운행이 없는 시간대(심야)·외곽 노선은 대부분 미확인

## 7. 구현 영향 (승인 후 TASK-017 시간 산정 부분)

- 서버: 노선별 예측 조회 필요 — `/api/arrivals?routeId=…`(노선 ID만, 좌표 없음) 추가 → **D-30**(노선 ID가 접근 로그·CDN 캐시 키에 남음. 정류장 ID 요청(D-22)과 같은 성격). 상류는 `BusArriveInfo?route=…&station=<노선의 첫 정류장>`(값 무시되지만 필수)
- 호출량: 결과 화면의 경로(최대 8개 × 구간 최대 3)의 서로 다른 노선 수만큼 — 노선당 1회, 15초 CDN 캐시
- 브라우저: `TimeEstimator` 구현(§4 산식), 행 단위 신선도(D-04), 스냅샷 노선 대조
