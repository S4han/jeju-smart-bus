해석:

- 순번은 사용 중 행만 보면 결함이 없다 → **AC-008 "운행 방향상 앞"은 같은 `routeId` 안의 `stationOrd` 비교로 판정 가능.**
- 순환 노선 21개, 같은 정류장 반복 노선 58개 → 해석 규칙 필요(**D-21**, §5).

## 4. 정류장·노선 가공 규칙 제안 (**D-26 신규 — 사용자 승인 필요**)

1. 노선: `Bus.useYn=Y`만 사용. `useYn=A`(58개, 2017년 갱신 노선)는 미사용으로 간주
2. 경유 매핑: 사용 중 노선의 `StationRoute.useYn=Y` 행만 사용. `stationCnt`·`updnDir` 필드는 사용하지 않음
3. 좌표 유효 범위: 제주 본섬 + **추자도**(관측 범위 위도 33.94~33.96, 경도 126.29~126.33). 범위 밖 61개 중 60개가 추자도 정류장 → 정상. 나머지 1개(`406002082` 색달동(야크마을))는 경도·위도 뒤바뀜 → D-24 적용
4. 정류장이 1개 이하인 노선(사용 중 3개, 수요응답형·차고지 가상 노선 등)은 경로 탐색에서 제외
5. `routeTp=53`(명세에 없는 코드, 예: 600번 계열 "서귀포칼호텔(종점)", "제주국제공항(하차전용)")은 일반 노선과 같게 탐색에 포함하되 노선명 그대로 표시 — 하차 전용 등 운행 조건 정보는 데이터에 없음
6. 문자열 `"null"`은 값 없음

## 5. D-21 순환·회차 노선 해석 제안 (사용자 확정 필요)

근거: 방향은 `routeId`별 순번으로만 표현되고(`updnDir` 무의미), 순환 노선 21개, 정류장 반복 노선 58개.

**제안:**
- 한 노선 탑승 구간은 같은 `routeId`에서 `승차 순번 < 하차 순번`일 때만 유효(AC-008)
- 마지막 순번을 지나 첫 순번으로 이어서 타는 것은 허용하지 않음(순환 노선이라도 데이터의 1→N 순서 안에서만) — 보수적이지만 연결 불명 경로를 만들지 않음
- 같은 정류장이 여러 순번에 나오면 가능한 (승차, 하차) 조합 중 **하차 순번 − 승차 순번이 가장 작은 조합**을 사용
- 이 규칙으로 놓치는 경로(순환 노선 끝을 넘는 탑승)는 "경로 없음"으로 처리되며, TASK-020 경로 탐색 성공률 실측에서 영향 확인

|---|---|
| 같은 이름 정류장 묶음 | 1,761개 묶음, 3,747개 정류장 |
| 같은 이름 짝까지 최근접 거리 | 30m 이내 1,697 · 50m 이내 2,430 · 100m 이내 3,268 · 200m 이내 3,668 · 200m 초과 79 |
| 같은 이름 묶음의 방향(`dirTp`) | 대부분 반대 방향 쌍(N/S, E/W) — 예: 제주버스터미널 `405000153`(S)·`405000154`(N), 18m |
| 서로 다른 ID 정류장 쌍 | 30m 이내 935쌍 · 50m 1,418 · 100m 2,159 · 200m 3,727 · 좌표 완전 동일 0 |

해석: **도로 맞은편·인접 정류장은 서로 다른 ID**이며, 같은 ID 공유는 "같은 쪽 같은 정류장"뿐이다.

**선택지:**
- (A) **같은 정류장 ID에서만 환승** — 연결이 데이터로 검증됨(AC-009). 길 건너 환승은 경로에서 빠짐
- (B) (A) + **같은 이름이고 N m 이내인 다른 ID 정류장 간 도보 환승 허용** — 경로 수 증가. 도보 거리·시간 근거가 필요해 D-06(도보시간 원천) 결정에 종속, 확정 전에는 해당 경로가 "시간 미확인" 영역으로 감

**제안: (A)로 MVP 시작**, TASK-020에서 경로 탐색 성공률을 실측한 뒤 (B)(N=50m 후보)를 재검토. 이유: AC-009의 "연결이 검증된 경로만"을 가장 엄격히 지키고, 도보시간 원천(D-06)이 정해지지 않았음.
