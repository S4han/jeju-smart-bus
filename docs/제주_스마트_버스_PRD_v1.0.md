## 1. 제품 개요

제주도민과 관광객이 모바일 웹에서 주변 버스 정류장, 실시간 버스 도착정보, 출발지부터 목적지까지의 버스 이용 경로를 확인하는 서비스다. 경로 탐색 및 기본 설명은 **규칙 기반**으로 제공한다. 생성형 AI를 활용한 선택적 설명은 후속 버전으로 분리한다.

- **주요 사용자:** 제주도민, 제주 방문 관광객.
- **플랫폼:** 모바일 웹.
- **핵심 가치:** 흩어진 버스 정보를 통합하고, 승차·환승·하차까지 연결된 이동 의사결정을 지원한다.
- **기존 PoC 참고:** React·TypeScript·Vite 기반 모바일 웹, NAVER Dynamic Map 표시 검증. 저장소 `S4han/jeju-smart-bus`, 배포 주소 `https://jeju-smart-bus-psi.vercel.app/`. PoC 지도 표시 경험이 실제 버스 API·경로 엔진의 동작을 보장하지는 않는다.

## 2. 해결할 문제와 목표 (STEP 1)

### 2.1 문제

- 사용자 위치에서 가까운 정류장과 버스 도착정보를 확인하고 목적지 이동 경로까지 파악하는 과정이 번거롭다.
- 여러 버스 노선과 환승 가능성을 비교할 때 실제 소요시간과 이동 단계를 판단하기 어렵다.
- 실시간 도착정보 누락, 위치 권한 거부, 외부 API 장애 등에서 사용자가 무엇을 할 수 있는지 불명확해질 수 있다.

### 2.2 목표

1. 현재 위치 또는 수동 지정 위치를 기준으로 이용 가능한 정류장을 찾는다.
2. 정류장별 실시간 도착정보를 확인한다.
3. 목적지까지 직행 또는 최대 두 번 환승하는 경로를 탐색한다.
4. 총 소요시간이 검증 가능하면 가장 짧은 경로를 우선 제시한다.
5. 소요시간을 산정할 수 없어도 연결관계가 검증된 경로는 명확히 구분해 제공한다.
6. 데이터가 불충분하거나 외부 서비스가 장애를 일으켜도 추측한 정보를 사실처럼 제공하지 않는다.

### 2.3 성공 지표

| 지표 | 측정 방법 | 목표 |
|---|---|---|
| 정류장 검색 응답시간 | 요청부터 정류장 결과 표시까지 | **미결정 — 개발 초기 실측 후 확정** |
| 경로 추천 응답시간 | 목적지 확정부터 결과 표시까지 | **미결정 — 개발 초기 실측 후 확정** |
| 경로 탐색 성공률 | 경로가 존재하는 검증 사례 중 정상 탐색 비율 | **미결정 — 개발 초기 실측 후 확정** |
| 경로 정확도 | 실제 노선·정차 순서·환승 연결과 대조 | **미결정 — 개발 초기 실측 후 확정** |
| 총 소요시간 추정 오차 | 추정값과 실제 관측 이동시간 비교 | **미결정 — 개발 초기 실측 후 확정** |
| 월 외부 서비스 과금 | 실제 과금 내역 확인 | **0원 — 확정** |

## 3. 사용자와 핵심 정책 (STEP 1~2)

- **주요 사용자:** 제주도민 및 관광객.
- **기본 출발지:** 사용자 현재 위치. 위치 권한 거부 또는 이용 불가 시 수동 입력 가능.
- **정류장 후보:** 출발지와 목적지 각각 기본 반경 500m. 후보가 0건이면 안내 후 사용자 동의를 받아 해당 위치만 1km까지 재검색. 동의 없이 자동 확대하지 않으며 1km 초과 자동 확대도 하지 않음.
- **경로:** 직행 및 최대 2회 환승.
- **총 소요시간:** 도보시간 + 버스 대기시간 + 버스 이동시간 + 환승에 필요한 시간. 중복 계산을 방지하는 상세 산식과 데이터 원천은 개발 초기 검증 대상으로 둠.
- **시간 산정 가능 추천:** 총 소요시간 오름차순 → 환승 횟수 오름차순 → 도보시간 오름차순 → 고정 경로 식별자 순. 최대 3개.
- **시간 산정 불가 경로:** 노선 연결관계가 검증된 경우에 한해 별도 영역에 최대 5개. 환승 횟수 오름차순 → 같은 환승 횟수 내 도보거리 확인 가능 경로 우선 → 확인 가능 경로끼리 도보거리 오름차순 → 같은 거리 또는 거리 확인 불가 경로끼리 고정 식별자 순.
- **실시간 정보 누락:** 검증된 시간표·운행 데이터가 있으면 추정치임을 표시. 검증 가능한 시간 근거가 없으면 시간을 만들어 내지 않음.
- **설명:** MVP에서는 규칙 기반 설명 제공. 생성형 AI 설명은 사용자 선택형 후속 기능.
- **월 운영비:** 외부 서비스 과금 월 0원 필수. 무료 한도 소진 시 추가 과금 없이 해당 기능 중단 및 사유 안내.
- **위치정보:** 서버 DB에 영구 저장하지 않고 요청 처리에만 사용. 로그·캐시 최소화, 외부 API 처리 조건은 개발 착수 전 필수 검증.

## 4. 요구사항 확인 결과 (STEP 2)

| 항목 | 결정 또는 확인 결과 |
|---|---|
| 버스 데이터 | 기존 제주 BIS API 정의 문서의 정류장·노선·도착·위치 관련 인터페이스를 후보로 분석. 현재 실제 응답은 미검증 |
| API 실제 호출 | PRD 작성 단계에서는 수행하지 않음. 개발 단계에서 필수 수행 |

## 5. 사용자 시나리오 (STEP 3)

### US-001 — 주변 정류장 찾기

**시작:** 사용자가 모바일 웹을 연다. **행동:** 현재 위치 권한을 허용하거나 출발지를 지정한다. **응답:** 500m 내 정류장을 지도·목록으로 제공한다. 정류장이 없으면 1km 확대를 안내하고 사용자가 승인한 경우 재검색한다. **완료:** 이용 가능한 정류장과 위치를 확인한다. **예외:** 위치 권한 거부 시 US-005, 데이터 장애 시 US-007.

### US-002 — 정류장 도착정보 확인

**시작:** 사용자가 정류장을 선택한다. **행동:** 도착정보를 조회한다. **응답:** 검증된 실시간 도착정보를 제공하고 누락 시 정보 부재를 알린다. 시간표 추정이 가능한 경우 추정임을 구분한다. **완료:** 이용할 버스의 도착정보 또는 정보 부재 상태를 이해한다.

### US-003 — 목적지까지 버스 경로 추천

**시작:** 사용자가 출발지와 목적지를 지정한다. **행동:** 경로 검색을 실행한다. **응답:** 승차·하차 후보 정류장과 노선 정차 순서·방향을 검증해 직행 및 최대 2회 환승 경로를 찾고 총 소요시간 기준으로 최대 3개를 정렬한다. **완료:** 승차·환승·하차 단계를 확인한다.

### US-004 — 대체 경로와 환승 비교

**시작:** 복수의 유효 경로가 존재한다. **행동:** 추천 경로를 비교한다. **응답:** 총 소요시간, 환승 횟수, 도보시간 및 경로 단계를 비교 가능하게 제공한다. **완료:** 사용자에게 적합한 경로를 선택한다.

### US-005 — 위치 권한 거부 후 수동 출발지

**시작:** 사용자가 위치 권한을 거부하거나 GPS를 사용할 수 없다. **행동:** 출발지를 직접 입력·선택한다. **응답:** 선택한 출발지를 기준으로 정류장 및 경로 검색을 제공한다. **완료:** GPS 없이도 핵심 기능을 이용한다.

### US-006 — 실시간·소요시간 데이터 부재

**시작:** 실시간 도착정보나 이동시간 구성 데이터가 없다. **행동:** 경로 검색을 실행한다. **응답:** 검증된 시간표 데이터가 있으면 추정임을 표시하고, 총 소요시간은 알 수 없지만 연결이 검증된 경로는 별도 영역에 최대 5개 표시한다. **완료:** 사용자가 시간 정보의 신뢰 수준을 구별한다.

### US-007 — 경로 없음·API 장애·한도 소진

**시작:** 검색 가능한 경로가 없거나 외부 API에 오류가 발생한다. **행동:** 조회를 요청한다. **응답:** 원인에 맞는 안내를 제공하며 검증되지 않은 경로나 시간을 생성하지 않는다. 무료 한도 소진 시 추가 과금 없이 관련 기능을 중단한다. **완료:** 사용자가 결과 부재·장애 사유를 이해한다.

### US-008 — 경로 설명

**시작:** 사용자가 추천 경로를 확인한다. **행동:** 경로 선택 또는 설명 요청을 수행한다. **응답:** MVP는 규칙 기반으로 추천 이유를 설명한다. 후속 버전에서 사용자가 선택한 경우에만 생성형 AI 설명을 제공한다. **완료:** 사용자가 경로 선택 근거를 이해한다. **예외:** AI가 없어도 기본 기능 유지.

## 6. 기능 요구사항 및 수용 기준 (STEP 4)

> 우선순위: **Must** = MVP 필수, **Should** = 후속 버전 포함. FR 및 AC 식별자는 STEP 4 확정 번호를 유지한다. 세부 조건은 STEP 5~6 확정 정책을 반영한다.

### FR-001 — 현재 위치 기반 기본 출발지 [Must]
- **가치:** 출발지 입력 부담 감소.
- **요구:** 위치 권한 허용 시 현재 위치를 기본 출발지로 사용.
- **AC-001:** 권한 허용·좌표 확보 시 현재 위치가 출발지로 설정된다. 권한 거부·좌표 실패 시 강제 진행하지 않고 수동 입력을 제공한다.
- **관련:** US-001, US-003 / 위치 권한.

### FR-002 — 수동 출발지 입력 [Must]
- **가치:** GPS 없이 검색 가능.
- **요구:** 사용자가 출발지 장소 또는 위치를 수동 선택.
- **AC-002:** 위치 권한이 없어도 선택한 출발지로 정류장·경로 검색을 시작할 수 있다. 선택할 수 없는 입력은 유효한 출발지로 처리하지 않는다.
- **관련:** US-005 / 장소 검색 API U-001.

### FR-003 — 주변 정류장 검색 [Must]
- **가치:** 접근 가능한 승차 지점 확인.
- **요구:** 기본 반경 500m 정류장 검색, 0건이면 안내 후 1km 재검색.
- **AC-003:** 반경 500m 이내 정류장만 기본 결과에 포함한다. 0건일 때 1km 확대를 안내하며 사용자 동의 전에는 확대하지 않는다. 동의 후 1km까지 재검색하고 결과가 없으면 없다고 표시한다. 예시로 450m·500m 포함, 550m는 기본 결과에서 제외한다.
- **관련:** US-001 / 정류장 좌표·거리 계산.

### FR-004 — 정류장 지도·목록 동기화 [Must]
- **가치:** 정류장 위치를 쉽게 파악.
- **요구:** 동일한 정류장 검색 결과를 지도와 목록에 표현.
- **AC-004:** 목록과 지도는 동일한 유효 정류장 집합을 사용하고 선택한 정류장을 식별할 수 있다. 좌표가 없는 정류장을 임의 위치에 표시하지 않는다.
- **관련:** US-001 / 지도 API.

### FR-005 — 정류장별 도착정보 [Must]
- **가치:** 승차 대기 판단.
- **요구:** 선택 정류장의 검증된 실시간 도착정보 표시.
- **AC-005:** 선택한 정류장 ID로 도착정보를 조회하고 해당 정류장의 버스 도착정보만 표시한다. 응답이 없거나 오래된 경우 실시간 정보가 있는 것처럼 표현하지 않는다.
- **관련:** US-002 / 도착정보 API.

### FR-006 — 목적지 검색·선택 [Must]
- **가치:** 목적지 기반 이동 검색.
- **요구:** 목적지를 검색하고 위치를 확정.
- **AC-006:** 사용자가 검색 결과에서 목적지를 선택하면 유효한 목적지 좌표로 경로 탐색을 시작한다. 장소 검색 실패·선택 전에는 임의 목적지로 탐색하지 않는다.
- **관련:** US-003 / 장소 검색 API U-001.

### FR-007 — 승차·하차 후보 정류장 탐색 [Must]
- **가치:** 출발·도착 지점과 버스망 연결.
- **요구:** 출발지·목적지 각각 기본 500m 후보 탐색, 없으면 안내 후 동의한 위치만 1km 재검색.
- **AC-007:** 각 위치에서 500m 후보를 구한다. 후보가 없는 위치에만 확대 동의를 요청하고 동의한 위치에 한해 1km 재검색한다. 후보가 끝내 없으면 경로를 만들어 내지 않는다.
- **관련:** US-003 / 정류장 좌표.

### FR-008 — 유효 직행 경로 탐색 [Must]
- **가치:** 환승 없는 경로 식별.
- **요구:** 노선의 정류장 정차 순서·운행 방향을 검증해 직행 연결 판단.
- **AC-008:** 같은 노선이라도 출발 정류장이 도착 정류장보다 운행 방향상 앞에 있을 때만 직행으로 인정한다. 역방향·연결 불명 경로는 제외한다.
- **관련:** US-003 / GATE-02~03.

### FR-009 — 최대 2회 환승 경로 탐색 [Must]
- **가치:** 직행 외 대체 경로 제공.
- **요구:** 0·1·2회 환승 경로를 탐색.
- **AC-009:** 각 구간의 방향·정차 순서와 환승 정류장 연결이 검증된 경로만 유효하다. 환승 3회 이상 경로는 추천·시간 미확인 목록 모두에서 제외한다.
- **관련:** US-003~004 / GATE-02~03.

### FR-010 — 총 소요시간 산정 [Must]
- **가치:** 일관된 경로 비교.
- **요구:** 도보·대기·버스 이동·환승시간을 검증된 근거로 산정.
- **AC-010:** 각 구성요소가 계산 가능하면 총 소요시간을 합산하고 출처·추정 여부를 구분한다. 필수 구성요소가 검증되지 않으면 임의 수치로 채우지 않고 총 소요시간 미확인으로 처리한다. 중복 합산 방지 산식은 U-002로 검증한다.
- **관련:** US-003~004, US-006 / GATE-04~05.

### FR-011 — 추천 경로 정렬 [Must]
- **가치:** 가장 빠르고 간단한 경로 우선.
- **요구:** 총 소요시간 → 환승 횟수 → 도보시간 → 고정 경로 식별자 순.
- **AC-011:** 50분/0회/5분 경로는 50분/0회/12분보다 앞서고, 두 경로 모두 50분/1회/8분보다 앞선다. 55분/0회 경로는 그 뒤에 온다. 세 수치가 모두 같으면 고정 식별자 순이며 동일 입력의 정렬 결과는 항상 동일하다.
- **관련:** US-003~004 / U-003.

### FR-012 — 추천 경로 최대 3개 [Must]
- **가치:** 비교 부담 감소.
- **요구:** 시간 산정 가능한 유효 경로를 상위 3개까지 표시.
- **AC-012:** 유효 경로가 4개 이상이어도 FR-011 정렬 상위 3개만 시간 기준 추천 영역에 표시한다. 1~2개라면 존재하는 개수만 표시한다.
- **관련:** US-003~004 / FR-011.

### FR-013 — 상세 승차·환승·하차 안내 [Must]
- **가치:** 실제 이동 수행 지원.
- **요구:** 추천 경로별 도보 접근, 승차 정류장·노선, 환승 위치, 하차 정류장을 안내.
- **AC-013:** 각 경로에서 구간별 정류장·노선·환승 순서를 확인할 수 있다. 확인되지 않은 정류장명이나 경유 정보를 생성하지 않는다.
- **관련:** US-003~004 / 정류장·노선 데이터.

### FR-014 — 검증된 시간표 기반 대체 추정 [Must]
- **가치:** 실시간 도착정보가 없을 때도 제한된 안내 제공.
- **요구:** 실시간 정보 부재 시 검증된 시간표·운행정보가 있으면 추정치를 사용.
- **AC-014:** 실시간 도착정보가 없고 검증된 대체 데이터가 있을 때만 추정 정보를 제공하며 **실시간**과 **추정**을 명확히 구분한다. 대체 데이터도 없으면 추정치를 만들지 않는다.
- **관련:** US-002, US-006 / GATE-04.

### FR-015 — 총 소요시간 미확인 경로 분리 [Must]
- **가치:** 연결 가능한 경로를 버리지 않되 정확도를 과장하지 않음.
- **요구:** 연결관계가 검증된 시간 미확인 경로를 별도 영역에 최대 5개 표시.
- **AC-015:** 환승 횟수 오름차순으로 정렬한다. 같은 환승 횟수에서는 도보거리 확인 가능 경로를 먼저 배치하고, 확인 가능 경로끼리는 도보거리 오름차순, 같은 거리 또는 확인 불가 경로끼리는 고정 식별자 순으로 정렬한다. 상위 5개만 표시하며 총 소요시간을 임의 기입하지 않는다. 최대 환승 2회 제한을 준수한다.
- **관련:** US-006 / FR-009, U-003.

### FR-016 — 경로 없음·데이터 불일치 처리 [Must]
- **가치:** 잘못된 경로 추천 방지.
- **요구:** 유효 경로 없음, 정류장·노선 불일치 등을 구분해 안내.
- **AC-016:** 검증된 경로가 없으면 '검색 가능한 경로 없음' 또는 데이터 확인 불가를 표시하고, 정차 순서·방향·연결 불일치 경로는 제외한다.
- **관련:** US-007 / GATE-02~03.

### FR-017 — API 장애·쿼터·비용 대응 [Must]
- **가치:** 장애 시 투명한 서비스 제공과 비용 상한 준수.
- **요구:** API 오류·호출 제한·무료 한도 소진 시 안내 및 안전한 중단.
- **AC-017:** 장애 시 영향을 받는 기능과 정보 부재를 안내한다. 무료 한도 소진 상태에서는 추가 과금 유발 호출을 실행하지 않고 해당 기능을 중단한다. 검증되지 않은 대체 결과를 생성하지 않는다.
- **관련:** US-007 / NFR-001~002, GATE-06.

### FR-018 — 규칙 기반 경로 설명 [Must]
- **가치:** 추천 이유 이해.
- **요구:** 검증된 경로의 소요시간·환승·도보시간 등 정렬 근거를 규칙으로 설명.
- **AC-018:** 생성형 AI 호출 없이도 경로별 추천 근거를 표시한다. 근거 데이터가 없는 항목을 설명에 포함하지 않는다.
- **관련:** US-008 / FR-011.

### FR-019 — 선택적 생성형 AI 경로 설명 [Should · 후속 버전]
- **가치:** 사용자 친화적인 경로 비교 설명.
- **요구:** 사용자가 선택한 경우 검증된 경로 데이터에 한해 생성형 AI로 설명.
- **AC-019:** AI 기능이 도입된 후 사용자 요청 시에만 호출하며, AI 실패·무료 한도 소진 시 기본 경로 검색과 FR-018 설명은 계속 이용 가능해야 한다. 모델·요금·보안 검증 전에는 기능을 활성화하지 않는다.
- **관련:** US-008 / U-005, NFR-005.

### FR-020 — 지도 기반 정류장·경로 표시 [Must]
- **가치:** 경로 공간적 이해.
- **요구:** 확인된 정류장·환승 지점과 경로 단계를 지도에 표시.
- **AC-020:** 유효 좌표가 있는 정류장과 경로 지점을 표시한다. 실제 도로·버스 운행 궤적 데이터가 없으면 추정 선을 실제 운행 경로처럼 표현하지 않는다.
- **관련:** US-001, US-003 / 지도 API.

## 7. 비기능 요구사항과 제약 (STEP 5~6)

| ID | 요구사항 | 검증 기준/상태 |
|---|---|---|
| NFR-001 | **월 외부 서비스 과금 0원 상한** | 실제 과금 내역 0원; 사용자 확정 |
| NFR-002 | 무료 호출 한도 소진 시 추가 과금 없이 기능 중단·안내 | 한도 소진 테스트에서 유료 호출 0건; 사용자 확정 |
| NFR-003 | API 인증키를 클라이언트·공개 저장소·로그에 노출 금지 | 비밀정보 관리 및 로그 검증; 기존 보안 원칙 |
| NFR-004 | 검증되지 않은 정류장·노선·시간 생성 금지 | 데이터 누락·불일치 테스트에서 임의 정보 표시 없음; 확정 |

| NFR-006 | 위치정보 서버 DB 영구 저장 금지, 요청 처리에만 사용. 로그·캐시 최소화 및 외부 API 처리 검증 | PRIV-001~004를 개발 착수 전에 확인; 확정 정책 |

**운영 정책:** 무료 제공 여부·초과 과금 방지 수단이 검증되지 않은 외부 서비스는 운영에 적용하지 않는다. 무료 한도 초과로 과금이 자동 발생하는 구조라면 사전 차단 장치가 검증될 때까지 사용하지 않는다.

## 8. MVP 포함·제외 범위 (STEP 5)

### 8.1 MVP 포함 — Must 19개

FR-001~FR-018, FR-020: 현재 위치/수동 출발지, 기본 500m 및 동의 후 1km 정류장 검색, 정류장 지도·목록, 실시간 도착정보, 목적지 검색, 유효 직행 및 최대 2회 환승 탐색, 총 소요시간 산정·정렬·최대 3개 추천, 상세 경로, 시간표 추정, 소요시간 미확인 경로 최대 5개, 데이터 오류·API 장애 대응, 규칙 기반 설명, 지도 표시.

### 8.2 후속 버전 포함

- **FR-019:** 선택적 생성형 AI 경로 설명. 모델·비용·호출 제한·보안 정책은 후속 버전에서 검증.

### 8.3 이번 MVP 제외 및 향후 검토

회원가입, 즐겨찾기, 하차 알림, 푸시 알림, 실시간 차량 위치 추적 전용 화면, 음성 대화형 Agent, 다국어 UI, 교통카드 결제 연동. **후속 개발 여부는 미확정**이다.

| U-007 | 성능·정확도 KPI 수치 | 개발 초기 실측 후 |

**해결된 사항:** U-004(도보거리 확인 가능·불가 경로 혼합 정렬), U-008(월 0원 운영비 정책), U-010(500m 결과 없음 시 안내 후 1km 재검색)은 사용자 결정으로 종료. U-009는 정책 미결정이 아니라 **확정된 개인정보 정책의 구현·검증 미완료**를 의미한다.

**가정 및 제약:** 경로 식별자는 동일 입력에서 안정적으로 비교 가능해야 하며 구체적 생성 규칙은 U-003이다. 버스 API와 시간 데이터가 충분하다는 전제는 아직 입증되지 않았다. 지도 PoC 성공은 버스 경로 추천 기능 검증과 별개다.
